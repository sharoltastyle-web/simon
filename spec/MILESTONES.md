## Development Execution Rules — הוראות ל־AI המבצע

1. יש לפתח את ה־Milestones לפי הסדר המוגדר להלן.
2. לאחר השלמת כל Milestone יש לעצור את הפיתוח ולהציג למשתמש את התוצר העובד ואת תוצאות הבדיקות מול כל סעיף ב־Definition of Done.
3. אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמש. שתיקה אינה אישור.
4. בדיווח יש להבחין בין בדיקות שעברו, בדיקות שנכשלו ובדיקות שלא בוצעו. אין להציג בדיקה שלא בוצעה כהצלחה. תנאי חובה שלא נבדק משאיר את אבן הדרך פתוחה.
5. יש לתקן כשלים בתוך אבן הדרך הנוכחית ולבדוק שוב את ההתנהגות שנפגעה לפני בקשת האישור למעבר.
6. כל תוצר ביניים נשאר בתחום אבן הדרך. יכולת שעדיין לא מומשה תסומן בדיווח ככזו; אין להציג את המוצר כמושלם לפני השלמת כל אבני הדרך.

הפרויקט הוא Frontend בלבד. אין הקמת Database, שירות Backend, Authentication או Database Migrations. הפיתוח והבדיקות המקומיות מופרדים מהאתר החי ב־GitHub Pages; אין צורך בסביבות Cloud נוספות.

## Milestone 1 — כניסה למשחק וקריאת הוראות ✅

### שם ומטרה

להעמיד מעטפת אפליקציה עובדת שבה המשתמש רואה את מסך הבית, פותח את אודות וקורא הוראות. הקמת כלי הפיתוח נעשית כחלק מיכולת משתמש זו.

### מה יש לממש

- פרויקט Vite בתבנית vanilla-ts, TypeScript strict, CSS מקומי ו־Node.js 24 LTS, עם npm ו־Lockfile.
- Git Repository וקוד מקור ב־GitHub; ללא פריסה בשלב זה. אם נדרשת פעולה בחשבון המשתמש, להדריך אותו באופן ממוקד להשלמתה, ללא העלאת סודות או יצירת שירותים שאינם נדרשים.
- שני המסכים, ניווט Hash ביניהם, ועברית ב־RTL.
- מסך בית עם Header, „שלב: 0 מתוך 10”, „ניקוד: 0”, לוח 2×2 וכפתור „התחל”.
- מסך אודות עם התיאור, ההוראות ושני כרטיסי הניקוד במצב „טרם שוחק משחק”.
- מראה בהתאם ל־DESIGN ול־Mockups: בסיס כהה, צבעי המשחק, טיפוגרפיה, כפתור ראשי כסוף ופינות מעוגלות. אין המרת הלוח לעיגול.

### תוצר מצופה

אפליקציה ניתנת לפתיחה בשרת הפיתוח וב־Build מקומי, עם שני מסכים מעוצבים וניווט עובד. מנגנון המשחק עדיין אינו ממומש; הדבר מצוין בדיווח למשתמש, ללא הוספת הודעת מוצר או מסך חדש.

### Definition of Done

- [ ] התקנה נקייה באמצעות `npm ci`, בדיקת `tsc --noEmit` ו־`vite build` מסתיימות בהצלחה.
- [ ] מעבר בית → אודות → בית עובד ללא טעינה מלאה; פתיחה ישירה ב־Hash של אודות מציגה מסך תקין.
- [ ] בדיקה חזותית מול שלוש תמונות המקור מאשרת שני מסכים בלבד, תוכן תואם וללא רכיבי UI נוספים.
- [ ] מיקומי הצבעים נכונים: כחול ימין־עליון, אדום שמאל־עליון, צהוב ימין־תחתון, ירוק שמאל־תחתון.
- [ ] במידות טלפון אין חיתוך כפתורים או גלילה אופקית; תוכן אודות ניתן לגלילה אנכית לפי הצורך. הטקסט העברי והמספרים קריאים, ואזורי המגע עומדים במינימום 48px.
- [ ] הקוד ותצורת ההתקנה שמורים ב־GitHub ללא node_modules או סודות.

## Milestone 2 — משחק מלא עם אורות, צלילים ותוצאה

### שם ומטרה

לאפשר לשחקן להשלים משחק מהתחלה ועד סיום, עם כל חוקי הרצף, מגבלת הזמן והמשוב.

### מה יש לממש

- Game Engine, Controller ו־Scheduler מקומיים, עם State Machine ומקור אמת יחיד בזיכרון.
- התחלה ברצף אקראי של צבע אחד; הוספת צבע אחד לכל שלב עד 10, ללא שינוי הרצף הקודם ועם אפשרות לחזרות.
- תצוגת רצף מסונכרנת של הארה וצליל מובחן לכל צבע באמצעות Web Audio API; משוב גם בלחיצת השחקן.
- חמש שניות לכל לחיצה, החל מסיום הצגת הרצף ואיפוס לאחר כל לחיצה נכונה שאינה האחרונה.
- סיום בטעות הראשונה או בתום הזמן; ניקוד לפי מספר שלבים שהושלמו; ניצחון לאחר שלב 10; התחלת משחק נוסף.
- משוב שלב, תור ותוצאה בתוך מסך הבית; חסימת קלט שאינו מותר וביטול Callbacks ישנים.
- טיפול בכשל אודיו בהודעה בעברית, בלי קריסת המשחק, בהתאם ל־PRD.

### תוצר מצופה

משחק מלא שעובד כל עוד מסך הבית גלוי. התוצאות מוצגות בבית. שמירת הישגים והשהיה יושלמו באבן הדרך הבאה.

### Definition of Done

- [ ] לחיצה על „התחל” יוצרת משחק יחיד; לחיצות חוזרות בזמן משחק אינן פותחות משחקים מקבילים.
- [ ] בדיקות Vitest עם אקראיות נשלטת מאשרות רצף מצטבר, חזרות על צבע ואורך של 1–10. אין שלב 11.
- [ ] טיימרים מבוקרים מאשרים שהשעון מתחיל אחרי ההצגה, מתאפס לכל לחיצה נכונה ועוצר במעבר שלב. לחיצה במועד ה־Deadline או אחריו מסתיימת בתום הזמן.
- [ ] נבדקו תוצאות 0 בכישלון בשלב 1, תוצאה 6 בכישלון בשלב 7 ותוצאה 10 בניצחון.
- [ ] קלט בזמן הצגת רצף אינו נקלט; לחיצות עודפות אינן מועברות לשלב הבא; משחק שסיים אינו ממשיך בעקבות Timer ישן.
- [ ] בדיקת דפדפן מאשרת מעבר מלא מהתחלה לתוצאה ולמשחק חדש. התוצאה נשארת במסך הבית ואין מסך נוסף.
- [ ] בדיקה ידנית בנייד מאשרת ארבעה צלילים מובחנים והארות נפרדות, כולל שתי הופעות רצופות של אותו צבע. תועד גם הטיפול בכשל השמעה.
- [ ] בדיקת טיפוסים, Unit Tests ו־Build עוברים.

## Milestone 3 — המשכיות משחק והישגים מקומיים

### שם ומטרה

לאפשר יציאה וחזרה ללא הפסד אוטומטי, ולשמור את הישגי המשחק לצפייה במסך אודות גם לאחר רענון.

### מה יש לממש

- השהיה במעבר לאודות ובהסתרת הדף, עם ביטול Timers, אורות וצלילים שתוזמנו.
- חזרה רק כאשר הבית פעיל והדף גלוי: הצגת אותו רצף מחדש מתחילתו, איפוס התשובה החלקית וחמש שניות חדשות ללחיצה הראשונה.
- חידוש AudioContext; אם נדרשת מחוות משתמש, השארת המשחק מושהה עד הפעולה הנדרשת, כפי שהוגדר בארכיטקטורה.
- Score Storage עם Validation וכתיבת שני נתוני הניקוד ב־Local Storage בסיום משחק בלבד; הצגת הנתונים בכרטיסי אודות.
- טיפול בנתונים חסרים, לא תקינים או חסומים. רענון יוצר משחק ריק ואינו שומר תוצאה חלקית.

### תוצר מצופה

משחק Online שלם: אפשר לצאת לאודות או לאפליקציה אחרת ולחזור, לסיים משחק, לראות הישגים ולרענן בלי למחוק את שני נתוני הניקוד.

### Definition of Done

- [ ] השהיה נבדקה באמצע תצוגת רצף ובאמצע תשובה, גם דרך אודות וגם דרך הסתרת הדף. בזמן השהיה אין ספירת זמן או צליל מתוזמן.
- [ ] בחזרה מוצג אותו רצף בשלמותו, ללא הוספת צבע, שינוי ניקוד או שימור תשובה חלקית. חזרה לאודות כשהדף גלוי אינה מחדשת את המשחק מאחוריו.
- [ ] נבדק חידוש לאחר יציאה לאפליקציה אחרת בנייד, לרבות תרחיש שבו השמעה דורשת פעולה נוספת. הזמן אינו מתחיל לפני שהרצף הוצג מחדש.
- [ ] תוצאת המשחק האחרון מתעדכנת גם כשהיא נמוכה מהשיא; השיא אינו יורד. תוצאה 0 נשמרת כתוצאה תקינה ונבדלת מ־„טרם שוחק משחק”.
- [ ] רענון באמצע משחק מאפס Session בלי לעדכן תוצאה חלקית; שני נתוני הניקוד מהמשחק שהושלם קודם נשארים.
- [ ] בדיקות Storage מכסות JSON פגום, ערכים מחוץ לטווח, נתונים חסרים וכשל גישה/כתיבה. כשל שמירה מוצג בעברית ואינו מונע משחק.
- [ ] אין אחסון מתמשך של רצף, שלב או תשובה חלקית; אין שחזור משחק לאחר טעינה חדשה.
- [ ] בדיקות טיפוסים, Unit Tests, תרחישי הדפדפן הקיימים ו־Build עוברים.

## Milestone 4 — משחק מותקן ו־Offline

### שם ומטרה

לאפשר שימוש במשחק המלא ללא אינטרנט לאחר הכנת המשאבים, והתקנת PWA במכשירים תומכים, ללא שינוי שני המסכים.

### מה יש לממש

- Manifest בעברית, אייקונים מקומיים, start_url ו־scope עקביים עם base של הפרויקט.
- vite-plugin-pwa עם Workbox generateSW ו־Precache של כל המשאבים החיוניים, ללא תלות ב־CDN או בפונטים מרוחקים.
- רישום Service Worker, Cache ייחודי לפרויקט והגבלת שליטתו לנתיב הפרויקט.
- עדכון Worker במצב המתנה ללא רענון אוטומטי בזמן משחק וללא דיאלוג או מסך חדש.
- בדיקת PWA מול Production Build המוגש מקומית; בדיקת התקנה בנייד על סביבת HTTPS לצורכי בדיקה, אם נדרשת לפני הפריסה הסופית. אין להסתמך על HTTP דרך כתובת רשת מקומית כתחליף ל־HTTPS.

### תוצר מצופה

תוצר Build שפועל Offline אחרי טעינה והכנת Cache, וכולל מעטפת התקנה תקינה. בדיקת התקנה על הכתובת החיה הסופית תושלם גם באבן דרך 5.

### Definition of Done

- [ ] Manifest, אייקונים, Service Worker ומשאבי המשחק נטענים בהצלחה גם כאשר האתר מוגש תחת נתיב משנה.
- [ ] לאחר Precache מוצלח ניתן לנתק רשת, לטעון מחדש באותו Browser Context, לפתוח בית ואודות, לשחק עם צלילים ולשמור ולקרוא ניקוד.
- [ ] תרחיש Offline נבדק על Build אמיתי ב־Playwright; אין משאב חיוני שמתבקש רק משרת חיצוני.
- [ ] פתיחה ראשונה ללא Cache וכשל רישום Service Worker אינם מתוארים כיכולת Offline שהושלמה; כשל ברישום אינו משבית משחק Online.
- [ ] בדיקה עם שתי גרסאות מאשרת שעדכון ממתין אינו קוטע משחק, שהגרסה החדשה נטענת לאחר מחזור ההחלפה הרלוונטי ושניקוד מקומי אינו נמחק.
- [ ] תועדו תוצאות בדיקת התקנה ופתיחה בנייד תומך, או מגבלת סביבת בדיקה. אם לא ניתן לבדוק התקנה לפני האירוח החי, הסעיף נשאר במפורש לבדיקה באבן דרך 5 ואינו מדווח כהצלחה.
- [ ] שאר הבדיקות וה־Build עוברים, ללא הוספת מסכים או יכולות שאינן במקורות.

## Milestone 5 — פרסום אוטומטי ואימות המוצר החי

### שם ומטרה

להעמיד אתר ציבורי עובד ב־GitHub Pages, עם בדיקות ופריסה אוטומטית מכל שינוי ב־main, ולהשלים אימות בנייד וב־PWA על הכתובת הסופית.

### מה יש לממש

- הגדרת GitHub Pages עם Source של GitHub Actions, כתובת HTTPS ו־base תואם לשם ה־Repository או לכתובת השורש.
- Workflow לפי הארכיטקטורה: התקנה נקייה, בדיקת טיפוסים, Vitest, Build, Playwright מול ה־Build, העלאת Artifact ופריסה רק לאחר הצלחת הבדיקות.
- בדיקות ל־Pull Requests ללא פריסתם ל־Production; הרשאות מינימליות ו־Concurrency למניעת פריסות מתנגשות.
- בדיקת המוצר החי, התקנה ומצב Standalone, Offline ועדכון PWA. אימות חזותי מול DESIGN ו־Mockups.
- תיעוד כתובת האתר ומנגנון Rollback באמצעות Revert ופריסה מחדש, תוך ציון שמכשיר עם Worker פעיל עשוי להמשיך להציג גרסה קודמת עד החלפתו.

### תוצר מצופה

משחק נגיש בכתובת ציבורית, עם כל היכולות המאושרות ומנגנון Deployment אוטומטי. אין צורך בתהליך העלאת קבצים ידני בכל עדכון.

### Definition of Done

- [ ] הקוד נשמר ב־GitHub; דחיפה ל־main מפיקה Deployment מוצלח ב־Actions והאתר זמין ב־HTTPS.
- [ ] Pipeline מאמת טיפוסים, Unit Tests ותרחישי דפדפן מול Build. כשל אימות מונע פריסה; Pull Request אינו מחליף את האתר החי.
- [ ] הכתובת הסופית, נתיבי המשאבים, Hash Navigation, Manifest ו־Service Worker פועלים ללא שגיאות 404 וללא שליטה מחוץ ל־scope של המשחק.
- [ ] במכשירי Android/Chrome ו־iOS/Safari נבדקו שני המסכים, מגע, אודיו, השהיה וחזרה, שמירת ניקוד ורענון, ללא חיתוך תוכן. נרשמו המכשירים והגרסאות שנבדקו.
- [ ] ההתקנה דרך מנגנון המכשיר ופתיחה כ־PWA נבדקו בפועל במכשירים התומכים, לרבות בדיקת התקנה שנדחתה מאבן דרך 4.
- [ ] על האתר החי נבדקו משחק Offline לאחר הכנת Cache, פתיחה מחדש ללא רשת והישארות הניקוד, בכפוף למגבלות האחסון שתועדו.
- [ ] נבדקה פריסת עדכון ללא קטיעת משחק פתוח וללא מחיקת הישגים; תוצאות הבדיקה מבחינות בין הגרסה שנפרסה לגרסה שמכשיר מסוים מציג בפועל.
- [ ] תועדה בדיקת Rollback או חזרה מבוקרת לגרסה קודמת, כולל השלכות Cache. אין הצגה של שינוי באתר החי כהצלחה ללא אימות תוצאתו.

## פורמט הצגת השלמה למשתמש

בתום כל Milestone יש להציג בקצרה: מה עובד כעת, כיצד לפתוח ולבדוק אותו, תוצאות מול סעיפי ה־Definition of Done, ומגבלות שנותרו. לאחר מכן יש לבקש אישור מפורש למעבר לאבן הדרך הבאה ולעצור. בסיום אבן הדרך האחרונה יש להציג את התוצר הסופי ואת תוצאות האימות.
