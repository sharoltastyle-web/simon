## החלטות מימוש ל־Milestone זה

1. **פירוק ל־Modules לפי ARCHITECTURE §2:**
   - `engine.ts` — חוקי המשחק בלבד, פונקציות טהורות, בלי DOM / זמן / אודיו.
   - `controller.ts` — State Machine, תזמון (הצגה, Deadline), תיאום Engine + View + Audio. הגורם היחיד שמתזמן תופעות לוואי.
   - `audio.ts` — Audio Adapter על Web Audio API.
   - `homeView.ts` — עדכון ה־DOM של מסך הבית (שלב, ניקוד, הודעה, הארה, זמינות „התחל”), וחיבור אירועי `click`.
   - `main.ts` — חיבור החלקים.
2. **הזרקת תלויות לבדיקות:** ה־Controller מקבל `now()`, `random()`, `setTimeout`/`clearTimeout`, View ו־Audio כפרמטרים (ברירת מחדל: `performance.now`, `Math.random`, הטיימרים של הדפדפן). בבדיקות: `vi.useFakeTimers()` + `now` שמבוסס על השעון המדומה, ו־View/Audio מדומים שמתעדים קריאות. אין ספרייה נוספת.
3. **מזהה ריצה (runId):** כל משחק וכל הצגת רצף מקבלים מספר. כל Callback מתוזמן בודק שה־runId עדיין עדכני, אחרת לא עושה כלום. סיום / משחק חדש מבטלים את כל הטיימרים (`cancelAll`) ועוצרים צלילים פעילים. סיום הוא Idempotent.
4. **זמנים (Constants ב־`controller.ts`, לפי ARCHITECTURE §3):** הארה + צליל 500ms לכל צבע; כיבוי 200ms בין צבעים; 500ms לפני הצגת שלב חדש; 5000ms לכל לחיצה. משוב לחיצת שחקן: הארה + צליל קצר של 250ms (הנחת מימוש, Constant).
5. **Deadline:** `deadline = now() + 5000` מיד אחרי כיבוי הצבע האחרון בהצגה, ומחדש אחרי כל לחיצה נכונה שאינה האחרונה. טיימר מתוזמן ל־Deadline רק „מעורר” סיום. בכל לחיצה בודקים קודם `now() >= deadline` ← תום הזמן (גם אם הטיימר טרם רץ). לחיצה אחרונה נכונה מבטלת את ה־Deadline.
6. **אקראיות:** `Math.floor(random() * 4)` (עם הגבלה ל־3 ליתר ביטחון) ממופה ל־`['blue','red','yellow','green']`. חזרות מותרות.
7. **קלט:** אירוע `click` יחיד לכל כפתור (מגע + מקלדת). לחיצה נקלטת רק ב־`awaitingInput`; בכל מצב אחר מתעלמים ממנה (בלי משוב ובלי כישלון). כפתורי הצבע לא מקבלים `disabled` (המראה שלהם לא משתנה) — החסימה לוגית בלבד. „התחל” מקבל `disabled` כשמשחק פעיל (הסגנון כבר קיים ב־`style.css`), וזמין ב־idle וב־finished. הגנה כפולה: גם ה־Controller מתעלם מ־`start()` בזמן משחק.
8. **אודיו (ARCHITECTURE §4):** AudioContext יחיד נוצר / מחודש (`resume()`) מתוך לחיצת „התחל”. לכל צבע OscillatorNode בתדר קבוע: כחול 261.63, אדום 329.63, צהוב 392.00, ירוק 523.25 Hz, עם GainNode בעלייה וירידה קצרות (למניעת קליקים), עוצמה מתונה. ה־Adapter שומר את המתנדים הפעילים ו־`stopAll()` עוצר ומנתק אותם. האור והצליל מופעלים מאותה קריאה במתזמן.
9. **כשל אודיו:** אם אין `AudioContext`, אם יצירתו נכשלת, או אם אחרי `resume()` (עם המתנה מקסימלית קצרה של ~300ms) המצב אינו `running` — המשחק ממשיך באורות בלבד, וכל קריאה לצליל הופכת ללא־פעולה. המשחק לא מחכה לאודיו מעבר להמתנה הקצרה הזו.
   **החלטה שדורשת אישור שלך (ראה סוף המסמך):** איפה מוצגת ההודעה „לא ניתן להשמיע צלילים. אפשר להמשיך לשחק לפי האורות.” — ההצעה: היא מוצגת **במקום** „צפו ברצף” בהצגת הרצף הראשונה של המשחק, ובהמשך חוזרות ההודעות הרגילות.
10. **תצוגה במסך הבית:**
    - „שלב” = אורך הרצף הנוכחי (0 לפני משחק ראשון; בסיום נשאר השלב שבו הסתיים המשחק). „ניקוד” = `completedStages`.
    - הודעות לפי DESIGN: הצגה „צפו ברצף”; תור „תורכם”; טעות „טעות! התוצאה: N”; תום הזמן „נגמר הזמן! התוצאה: N”; ניצחון „ניצחתם! השלמתם את כל 10 השלבים”. הודעת סיום נשארת עד „התחל”. כל הטקסטים דרך `textContent`.
    - הארה = המחלקה `is-active` שכבר קיימת ב־`style.css`.
11. **Vitest:** גרסה 5.0.5 (Stable, תומכת ב־Vite 8 — נבדק ב־`npm view`), כתלות פיתוח, מקובעת ב־`package-lock.json`. הבדיקות רצות בסביבת Node (אין צורך ב־DOM, כי ה־View מדומה). קובצי בדיקה ליד הקוד: `src/*.test.ts` (נבדקים גם ב־`tsc`, ואינם נכנסים ל־Build כי אף קובץ לא מייבא אותם).

## State Machine (מימוש ב־`controller.ts`)

| מצב | נכנסים כש... | יוצאים ל... |
| --- | --- | --- |
| `idle` | טעינת הדף | `presenting` בלחיצת „התחל” |
| `presenting` | התחלה / השלמת שלב | `awaitingInput` בסיום ההצגה |
| `awaitingInput` | סוף הצגה | `awaitingInput` (לחיצה נכונה), `presenting` (שלב הושלם, פחות מ־10), `finished` (טעות / זמן / ניצחון) |
| `finished` | סיום | `presenting` במשחק חדש („התחל”) |

`paused` יתווסף ב־Milestone 3; ה־Controller ייבנה כך שקל להוסיף לו `pause()`/`resume()` (כל התזמון עובר דרך פונקציה אחת שמבטלת הכול).

## Engine (`engine.ts`)

```
type Color = 'blue' | 'red' | 'yellow' | 'green'
const COLORS, MAX_STAGES = 10
type Session = { sequence: Color[]; inputIndex: number; completedStages: number }
newSession(random) -> Session            // sequence באורך 1
checkInput(session, color) -> 'correct' | 'stageComplete' | 'win' | 'wrong'
advanceStage(session, random) -> Session // מוסיף צבע אחד לסוף, מאפס inputIndex
```
- `stageComplete` מעלה את `completedStages`; כשהוא מגיע ל־10 מוחזר `win` ואין שלב 11.
- הרצף הקודם לעולם אינו משתנה (העתקה + הוספה בסוף).

## Controller (`controller.ts`) — עיקרי ההתנהגות

- `start()`: אם המצב `presenting`/`awaitingInput` — מתעלם. אחרת: `cancelAll()`, runId חדש, אתחול אודיו (מתוך אותה לחיצה), Session חדש, עדכון שלב/ניקוד, `disabled` על „התחל”, הצגת רצף.
- `present()`: הודעה „צפו ברצף” (או הודעת כשל האודיו, לפי החלטה 9), ואז לכל צבע: הדלקה + צליל ← אחרי 500ms כיבוי ← 200ms ← הבא. אחרי כיבוי האחרון: `awaitingInput`, „תורכם”, Deadline.
- `press(color)`: רק ב־`awaitingInput`. בדיקת Deadline ← משוב אור וצליל 250ms ← `checkInput`:
  - `correct` → Deadline חדש.
  - `stageComplete` → ביטול Deadline, עדכון ניקוד, `presenting`, המתנה 500ms, `advanceStage`, עדכון שלב, הצגה.
  - `win` / `wrong` → `finish()`.
- `finish(outcome)`: Idempotent; `cancelAll()` (ההארה של משוב הלחיצה האחרונה נכבית בזמן), `finished`, הודעת התוצאה, „התחל” זמין. (שמירת הניקוד תתווסף ב־Milestone 3 בנקודה זו.)

## בדיקות (Vitest) — מיפוי ל־Definition of Done

**Engine:**
- עם `random` נשלט: רצף מתחיל באורך 1; כל שלב מוסיף בדיוק צבע אחד בסוף והקודם זהה.
- `random` שמחזיר תמיד אותו ערך → חזרות על אותו צבע מתקבלות.
- אורכים 1–10; אחרי השלמת שלב 10 מוחזר `win` ואין שלב 11.
- ניקוד: טעות בשלב 1 → 0; טעות בשלב 7 → 6; ניצחון → 10.

**Controller (טיימרים מדומים):**
- `start()` כפול / בזמן משחק — Session אחד בלבד, הרצף לא מוגרל מחדש.
- לחיצות בזמן הצגה מתעלמות ואינן נספרות.
- הזמן מתחיל רק אחרי סוף ההצגה (חלוף 5 שניות מתחילת ההצגה לא מסיים משחק).
- לחיצה נכונה מאפסת את הזמן ל־5 שניות; אחרי השלמת שלב הזמן נעצר (אין timeout במהלך הצגת השלב הבא).
- תום הזמן ← `timeout` עם הניקוד הנכון; לחיצה בדיוק ב־Deadline או אחריו ← `timeout`.
- לחיצות עודפות אחרי השלמת שלב (בזמן ההמתנה / הצגה) לא עוברות לשלב הבא.
- אחרי סיום — טיימר ישן לא משנה דבר; טעות ותום זמן כמעט יחד ← תוצאה אחת.
- משחק חדש אחרי סיום מתחיל משלב 1 ברצף חדש, וטיימרים מהמשחק הקודם לא משפיעים.
- כשל אודיו: המשחק ממשיך וההודעה מוצגת.

## שאלה פתוחה לפני הבנייה

**הודעת כשל הצליל:** ב־DESIGN מוצגת הודעה אחת בכל רגע, ולכן „צפו ברצף” היה מחליף מיד את ההודעה „לא ניתן להשמיע צלילים...”. ההצעה: להציג את הודעת הכשל במקום „צפו ברצף” בהצגה הראשונה של המשחק בלבד. אם תעדיף אחרת (למשל: להציג אותה במקום „צפו ברצף” בכל הצגה לאורך המשחק) — אמור לי לפני הבנייה.
