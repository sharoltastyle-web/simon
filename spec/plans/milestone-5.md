# תוכנית — Milestone 5: פרסום אוטומטי ואימות המוצר החי

תאריך: 19.10.2026. מבוסס על MILESTONES.md (Milestone 5), ARCHITECTURE.md (סעיפים 6, 8, 9, 10 ו־ADR-5) ו־PRD.md, ועל הקוד הקיים אחרי Milestone 4.

## מטרה בקצרה

המשחק זמין לכולם בכתובת `https://sharoltastyle-web.github.io/simon/`. כל דחיפה ל־main מריצה אוטומטית את כל הבדיקות, ורק אם כולן עוברות — האתר מתעדכן. Pull Request רק נבדק ולא מחליף את האתר. בסוף נבדקים האתר החי, ההתקנה בטלפון (שנדחתה מ־Milestone 4), Offline, עדכון גרסה וחזרה לגרסה קודמת. אין שינוי במסכים או בחוקי המשחק.

## מה כבר קיים ונבדק

- ה־Repository `sharoltastyle-web/simon` ציבורי ומחובר (ה־main המרוחק זהה ל־commit של Milestone 4). לפי ARCHITECTURE, Repository ציבורי מאפשר Pages ו־Actions ללא עלות.
- `base` כבר `/simon/` ותואם לשם ה־Repository (ADR-5), כולל Manifest, `scope` ו־Service Worker. אין צורך לשנות אותו.
- `.nvmrc` = 24, `package-lock.json` קיים, ו־`npm run build` / `npm run test:e2e` עובדים מקומית.
- אין עדיין תיקיית `.github` ואין CLI של GitHub (`gh`) במחשב — פעולות באתר GitHub ייעשו על ידי המשתמש, בהדרכה.

## החלטות לתכנון (לאישור המשתמש)

1. **סדר העבודה ודחיפות.** אי אפשר לבדוק אתר חי בלי לדחוף ל־GitHub, בעוד שלפי CLAUDE.md דחיפה רגילה היא גם אישור ה־Milestone. ההצעה:
   1. בונים מקומית את ה־Workflow ובודקים כל מה שאפשר בלי GitHub.
   2. **עוצרים ומבקשים אישור** לדחיפה ראשונה (commit של העבודה עד כאן). לפני הדחיפה המשתמש מפעיל את Pages (צעד 1 בהדרכה למטה).
   3. במהלך הבדיקות יידרשו עוד דחיפות קטנות (בדיקת עדכון, בדיקת Rollback, ענף ל־Pull Request). **כל אחת מהן תתבקש בנפרד**, עם הסבר מה היא עושה.
   4. אחרי שהכול נבדק — מסמנים 🟡. הדחיפה האחרונה, אחרי הבדיקות של המשתמש בטלפון, היא האישור (✅) כרגיל.
   הדחיפות בתוך התהליך **אינן** אישור של ה־Milestone.
2. **WebKit (Safari) ב־CI — הצעה: לא להוסיף.** ADR-5 השאיר את זה להחלטה כאן. בדיקת WebKit ב־CI אינה מוכיחה התנהגות של Safari מותקן ב־iOS (ARCHITECTURE §10), ומוסיפה זמן ותחזוקה. הבדיקה של iPhone אמיתי (סעיף 4 בבדיקות הטלפון) היא שמכסה את Safari. ה־CI נשאר Chromium בהדמיית טלפון.
3. **מכשירים לבדיקה.** ה־DoD דורש בדיקה גם ב־Android/Chrome וגם ב־iOS/Safari. **שאלה למשתמש:** אילו מכשירים זמינים לך? אם חסר אחד מהם — הסעיף נשאר פתוח ומדווח כ"לא בוצע", ולא כהצלחה.
4. **סימון גרסה בלתי נראה.** ב־CI ה־Build מקבל `SIMON_BUILD_ID` = ה־commit SHA (המנגנון הקיים מ־Milestone 4, שמסומן ב־`data-build` בלתי נראה). כך אפשר לראות בבדיקה איזו גרסה נפרסה ואיזו גרסה דפדפן מסוים מציג בפועל. אין שינוי בממשק.
5. **בדיקת Rollback — חזרה מבוקרת.** במקום לבטל קוד אמיתי: דוחפים שינוי קטן ובלתי מזיק (commit ריק "בדיקת עדכון", שיוצר גרסה חדשה בזכות סימון הגרסה), בודקים את העדכון, ואז עושים לו `git revert` ודוחפים — בודקים שהאתר חזר לפרוס מחדש, שהדפדפן עובר לגרסה החדשה רק אחרי סגירה ופתיחה מחדש, ושהניקוד נשאר. (כל דחיפה באישור נפרד, לפי החלטה 1.)
6. **בדיקת Pull Request עם כשל מכוון.** ענף זמני עם בדיקת Unit אחת שנכשלת בכוונה. ממנו נפתח Pull Request (המשתמש פותח באתר GitHub — אתן קישור). מצופה: הבדיקות אדומות, שלב הפריסה לא רץ, האתר החי לא השתנה. אחר כך סוגרים את ה־PR ומוחקים את הענף (באישור). זה מוכיח גם ש"כשל אימות מונע פריסה" וגם ש"PR אינו מחליף את האתר", בלי להכניס קוד שבור ל־main.

## ה־Workflow: `.github/workflows/deploy.yml`

- **מתי רץ:** `push` ל־`main`, `pull_request` ל־`main`, ו־`workflow_dispatch` (הפעלה ידנית מתוך GitHub, לפריסה מחדש בלי commit).
- **הרשאות ברירת מחדל:** `contents: read` בלבד ברמת ה־Workflow.
- **Job 1 — `verify`** (רץ בכל האירועים), על `ubuntu-latest`:
  1. `actions/checkout`
  2. `actions/setup-node` עם `node-version-file: .nvmrc` ו־`cache: npm`
  3. `npm ci`
  4. `npm run typecheck` (`tsc --noEmit`)
  5. `npm test` (`vitest run`)
  6. `npx vite build` עם `SIMON_BUILD_ID: ${{ github.sha }}`
  7. `npx playwright install --with-deps chromium`
  8. `npm run test:e2e` (עם `CI=true`, מול ה־`dist` משלב 6; בדיקת העדכון בונה בנפרד ל־`dist-e2e/` ואינה נוגעת ב־`dist`)
  9. רק ב־push ל־main / הפעלה ידנית: `actions/configure-pages` ו־`actions/upload-pages-artifact` עם `path: dist`
  10. בכשל: העלאת `playwright-report/` ו־`test-results/` כ־Artifact לעיון (שמירה לזמן קצר, כדי לא לבזבז מכסת אחסון).
- **Job 2 — `deploy`:** `needs: verify`, ורץ **רק** כש־`github.event_name` הוא `push` (ל־main) או `workflow_dispatch` מ־main. הרשאות `pages: write` ו־`id-token: write` רק כאן. `environment: github-pages` עם ה־URL של הפריסה. שלב יחיד: `actions/deploy-pages`.
- **Concurrency:** לפריסה — קבוצה `pages` עם `cancel-in-progress: false` (פריסה שהתחילה לא נקטעת, ואין שתי פריסות במקביל). לבדיקות PR — קבוצה לפי הענף עם `cancel-in-progress: true`.
- **גרסאות Actions:** רק Actions רשמיים של GitHub (`actions/*`), מקובעים לגרסה מלאה ומדויקת (למשל `vX.Y.Z`) — לבדוק בזמן הבנייה מהי הגרסה היציבה העדכנית של כל אחד, ולתעד ב־ADR-6.
- **כשל באחד השלבים** עוצר את `verify`, ולכן `deploy` לא רץ והאתר הקודם נשאר.

## בדיקות מקומיות לפני הדחיפה הראשונה

- `npm run build` ו־`npm run test:e2e` עוברים כמו היום (ההתנהגות המקומית לא השתנתה).
- הדמיית מצב CI מקומית: `npx vite build` עם `SIMON_BUILD_ID=test` ואז `CI=true npm run test:e2e` — עובר, וב־`dist/assets/*.js` מופיע הסימון `test` (כלומר הבדיקות רצו על ה־Build הזה ולא על Build חדש).
- בדיקת תחביר של ה־YAML (קריאה בכלי YAML; אם אפשר — `actionlint` דרך `npx` בלבד, בלי התקנה קבועה).

## הדרכת המשתמש באתר GitHub (צעד אחר צעד, בזמן הבנייה)

1. **לפני הדחיפה הראשונה:** ב־GitHub → ה־Repository `simon` → Settings → Pages → תחת "Build and deployment" לבחור Source: **GitHub Actions**. (בלי זה הפריסה הראשונה תיכשל.)
2. אחרי הדחיפה: לשונית **Actions** — לראות את הריצה ירוקה, ובסוף שלב ה־deploy מופיעה הכתובת.
3. לבדיקת ה־PR: לפתוח Pull Request מהענף הזמני (אתן קישור ישיר), לראות שהבדיקה אדומה ושה־deploy לא רץ, ולסגור את ה־PR.

## בדיקות על האתר החי (אני מבצע)

1. **Actions:** הריצה של ה־push הראשון ירוקה; זמן הריצה והשלבים מתועדים.
2. **`npm run test:e2e:live`** — בדיקות הבית/אודות/ניווט/ניקוד ו־Offline (Precache, ניתוק רשת, טעינה מחדש, משחק, שמירת ניקוד, `scope` = `/simon/`, אין בקשות לשרתים אחרים) רצות מול `https://sharoltastyle-web.github.io/simon/`.
3. **בדפדפן המובנה, בגודל טלפון:** אין שגיאות 404 ואין שגיאות בקונסול (Manifest, אייקונים, `sw.js`, גופנים, `#/about` בפתיחה ישירה); ה־Manifest נקרא נכון; `data-build` שווה ל־SHA של ה־commit שנפרס; צילומי מסך של שני המסכים להשוואה מול DESIGN ו־mockups.png.
4. **עדכון (החלטה 5, חלק א'):** בדפדפן המובנה פותחים משחק באתר החי, אחרי דחיפת commit הבדיקה ממתינים לסיום הפריסה, ובודקים: הדף הפתוח לא נטען מחדש, המשחק ממשיך, ה־`data-build` עדיין הישן (מה שהדפדפן מציג) למרות שה־SHA החדש כבר פורסם (מה שנפרס). אחרי סגירה ופתיחה מחדש — ה־`data-build` החדש, והניקוד נשאר.
5. **Rollback (החלטה 5, חלק ב'):** `git revert` ודחיפה, ואותה בדיקה שוב. מתועד: האתר החי חוזר לפרוס, ודפדפן עם Worker פעיל ממשיך להציג את הגרסה הקודמת עד סגירה ופתיחה מחדש.
6. **PR עם כשל מכוון (החלטה 6).**

## בדיקות בטלפון (המשתמש מבצע, לפי רשימה שאתן)

לכל מכשיר נרשמים: דגם, גרסת מערכת ההפעלה וגרסת הדפדפן.

1. פתיחת הכתובת: שני המסכים, אין חיתוך תוכן או גלילה הצידה, אודות נגלל.
2. משחק: מגע, אורות וארבעה צלילים מובחנים; השהיה במעבר לאודות ובמעבר לאפליקציה אחרת, וחזרה עם הצגת הרצף מחדש; סיום משחק, ניקוד באודות, רענון — הניקוד נשאר.
3. **התקנה:** Android — דרך תפריט Chrome ("התקנת אפליקציה" / "הוספה למסך הבית"); iPhone — דרך כפתור השיתוף ב־Safari ← "הוספה למסך הבית". פתיחה מהאייקון: נפתח בלי שורת כתובת (Standalone), עם השם והאייקון הנכונים.
4. **Offline:** אחרי פתיחה אחת עם רשת — מצב טיסה, פתיחה מהאייקון, משחק מלא, הניקוד נשמר ונשאר אחרי סגירה ופתיחה.
5. **עדכון:** בזמן הבדיקה שלי (סעיף 4 למעלה) משחק פתוח בטלפון לא נקטע והניקוד נשאר.

מגבלות שיתועדו ולא יוצגו כהצלחה: iOS עלול למחוק אחסון של אתר שלא נפתח זמן רב; מתג שקט בטלפון משתיק צלילים ואינו ניתן לזיהוי (ADR-2).

## ADR-6 שיתווסף ל־ARCHITECTURE.md

**פריסה אוטומטית ל־GitHub Pages:** Workflow יחיד `deploy.yml` עם Jobs `verify` ו־`deploy`; גרסאות ה־Actions שנבחרו; ה־Build נבנה פעם אחת עם `SIMON_BUILD_ID` = SHA, נבדק ב־Playwright ומועלה כמו שהוא; Chromium בלבד ב־CI (WebKit לא נוסף, לפי החלטה 2); כתובת האתר; נוהל Rollback: `git revert` ← push ← פריסה אוטומטית (או "Re-run" לריצה קודמת / הפעלה ידנית), כולל ההשלכה ש־Worker פעיל ממשיך להציג גרסה קודמת עד סגירת כל חלונות המשחק ופתיחה מחדש; מכשירים וגרסאות שנבדקו.

## מה לא נכלל

- אין Domain פרטי, Analytics, Secrets, שירות חיצוני נוסף או Backend.
- אין הודעת "גרסה חדשה", כפתור התקנה או כל רכיב ממשק חדש; אין שינוי בחוקי המשחק ובמראה.
- אין Branch Protection או כללי Repository נוספים (לא נדרשים ב־spec).
- אין שינוי ב־`base`, ב־Manifest או בהגדרות ה־PWA.
