# תוכנית — Milestone 3: המשכיות משחק והישגים מקומיים

תאריך: 19.10.2026. מקורות: `PRD.md` (זרימת „אודות והשהיה”, „ניקוד וסיום”, „השהיה וחזרה”, Edge Cases), `ARCHITECTURE.md` (§3 State Machine, השהיה וחידוש; §4 אודיו; §5 Data Model ואחסון; בדיקות), `DESIGN.md` (שורת ההודעה, כרטיסי אודות), `MILESTONES.md`, והקוד הקיים (`src/controller.ts`, `src/audio.ts`, `src/navigation.ts`, `src/homeView.ts`, `src/main.ts`, `index.html`).

## מטרה

1. **השהיה וחזרה:** מעבר לאודות, הסתרת הדף או מעבר לאפליקציה אחרת משהים את המשחק (בלי ספירת זמן, אור או צליל). חזרה לבית גלוי מציגה שוב את אותו רצף מתחילתו ונותנת 5 שניות ללחיצה הראשונה.
2. **הישגים מקומיים:** בסיום כל משחק נשמרים „תוצאת המשחק האחרון” ו־„השיא האישי” ב־Local Storage, ומוצגים בכרטיסי אודות — גם אחרי רענון.

**מחוץ ל־Milestone זה:** PWA / Offline / Service Worker ו־Playwright — Milestone 4. פריסה — Milestone 5. אין שינוי במבנה המסכים, אין מסך או חלון חדש.

## החלטות מימוש ל־Milestone זה

1. **מודולים חדשים (לפי ARCHITECTURE §2):**
   - `scoreStorage.ts` — Score Storage: קריאה, Validation וכתיבה של `ScoreRecord`.
   - `lifecycle.ts` — Lifecycle Adapter: מאזין ל־`visibilitychange`, `pagehide`, `pageshow` ולשינוי מסך, ומחליט מתי לשלוח `pause()` / `resumeIfPossible()` ל־Controller.
   - `aboutView.ts` — עדכון שני כרטיסי הניקוד באודות (`textContent` בלבד).
2. **מצב `paused` ב־Controller:** נכנסים אליו מ־`presenting` או מ־`awaitingInput` בלבד (ב־`idle` / `finished` השהיה לא עושה כלום). בכניסה: `runId` חדש, ביטול כל הטיימרים וה־Deadline, `audio.stopAll()`, כיבוי אורות, איפוס התשובה החלקית (`inputIndex = 0`). הרצף ו־`completedStages` נשמרים בזיכרון. „התחל” נשאר חסום (המשחק עדיין קיים). לחיצות על צבעים מתעלמות.
3. **מעבר שלב שנקטע:** היום הצבע החדש מוגרל רק אחרי ההמתנה של 500ms בין שלבים. כדי שהשהיה בדיוק ברגע הזה לא „תאבד” שלב או תגריל מחדש — הצבע החדש יתווסף לרצף **מיד** כשהשלב מושלם, וההמתנה של 500ms תהיה רק לפני ההצגה. כך „הרצף הנוכחי” תמיד מוגדר: חזרה מציגה אותו, בלי הגרלה נוספת ובלי שינוי ניקוד. מספר השלב בשורת המצב ממשיך להתעדכן ברגע תחילת ההצגה (ללא שינוי נראה לעין).
4. **מתי חוזרים:** רק כאשר שני התנאים מתקיימים — מסך הבית פעיל **וגם** הדף גלוי (`document.visibilityState === 'visible'`). Lifecycle בודק את שניהם בכל אירוע רלוונטי (`hashchange` לבית, `visibilitychange` ל־visible, `pageshow`). חזרה לאודות כשהדף גלוי משאירה את המשחק מושהה. שחזור מ־Back/Forward Cache לא מפעיל טיימרים ישנים — הם בוטלו בהשהיה, והחזרה מתחילה הצגה חדשה.
5. **חידוש האודיו בחזרה (ARCHITECTURE §4):**
   - אם האודיו כבר נכשל בתחילת המשחק — ממשיכים באורות בלבד, מציגים מיד.
   - אחרת: מנסים `audio.prepare()` (אותו `resume()` עם המתנה של עד 300ms). הצליח ← הצגת הרצף מחדש („צפו ברצף”).
   - נכשל (הדפדפן דורש נגיעה) ← המשחק **נשאר מושהה**, בשורת ההודעה מוצג „להמשך המשחק, הקישו כאן”, ואין ספירת זמן.
   - **„כאן” = שורת ההודעה עצמה.** כשההודעה הזו מוצגת, שורת ההודעה נעשית לחיצה (אזור מגע של לפחות 48px — כבר יש לה גובה קבוע של שתי שורות) ונגישה למקלדת. לחיצה עליה קוראת ל־`prepare()` מתוך הנגיעה ואז מציגה את הרצף. אם גם אז אין צליל — ממשיכים באורות בלבד, והצגה זו מתחילה בהודעת כשל הצליל (כמו ב־ADR-2). אין כפתור, חלון או מסך חדש; המראה של השורה לא משתנה.
6. **חזרה מתחילה תמיד הצגה מלאה** של כל הרצף הנוכחי, עם התזמונים הקיימים (500ms אור / 200ms הפסקה), ורק אחרי כיבוי הצבע האחרון — „תורכם” ו־Deadline של 5 שניות. השהיה כפולה / חזרה כפולה הן Idempotent (מוגנות ב־`runId`).
7. **הגנה נוספת בקלט:** `press()` בודק גם שהדף גלוי (לפי ARCHITECTURE §3), בנוסף למצב ול־Deadline.
8. **Score Storage (ARCHITECTURE §5):**
   - מפתח `simon-memory.scores.v1`; ערך JSON `{ schemaVersion: 1, bestScore, lastScore }`.
   - **קריאה:** `getItem` ו־`JSON.parse` עטופים ב־try/catch; כל ערך תקין רק אם הוא `null` או מספר שלם 0–10, אחרת נחשב חסר. אם יש `lastScore` תקין ו־`bestScore` חסר או קטן ממנו — `bestScore = lastScore`. כל כשל ← `{ bestScore: null, lastScore: null }` בלי קריסה.
   - **כתיבה — בסיום משחק בלבד:** קוראים שוב את הערך השמור, `bestScore = max(השמור, מה שבזיכרון, התוצאה)`, `lastScore = התוצאה`, וכתיבה אחת של JSON. מחזיר את הרשומה המעודכנת ו־`saved: true/false`.
   - גישה ל־`localStorage` עצמה עטופה (במצבי פרטיות היא יכולה לזרוק שגיאה כבר בגישה). ה־Storage מוזרק כפרמטר לצורך בדיקות.
9. **בסיום משחק (`finish`):** אחרי קביעת התוצאה — שמירה דרך Score Storage, עדכון כרטיסי אודות מהרשומה המעודכנת (גם אם השמירה נכשלה — הערכים נשארים בזיכרון עד רענון). אם השמירה נכשלה, ההודעה היא הודעת התוצאה ואחריה באותה שורה: „לא ניתן לשמור ניקוד במכשיר זה.” (לפי DESIGN). אין כתיבה ל־Storage בהתחלה, בהשהיה, בחזרה או ברענון.
10. **בטעינת הדף:** קריאת הניקוד והצגתו בכרטיסי אודות. `null` ← „טרם שוחק משחק”; מספר (כולל 0) ← המספר. Session ריק במצב `idle`. אין שמירה או שחזור של רצף, שלב או תשובה חלקית.
11. **`navigation.ts`:** יקבל אפשרות לרשום Callback לשינוי מסך, ופונקציה שמחזירה את המסך הפעיל — כדי ש־Lifecycle יידע מתי הבית פעיל. ההתנהגות הקיימת של הניווט לא משתנה.

## State Machine אחרי השינוי

| מצב | נכנסים כש... | יוצאים ל... |
| --- | --- | --- |
| `idle` | טעינת הדף | `presenting` („התחל”) |
| `presenting` | התחלה / שלב חדש / חזרה מהשהיה | `awaitingInput`, `paused` |
| `awaitingInput` | סוף הצגה | `awaitingInput`, `presenting`, `finished`, `paused` |
| `paused` | מעבר לאודות / הסתרת הדף / `pagehide` | `presenting` של אותו רצף, כשהבית פעיל והדף גלוי והאודיו מוכן (או אחרי הקשה על שורת ההודעה) |
| `finished` | טעות / זמן / ניצחון — כולל שמירת ניקוד פעם אחת | `presenting` („התחל”) |

ממשק ה־Controller מתרחב ב־`pause()`, `resumeIfPossible()` (נקרא מ־Lifecycle) ו־`continueFromTap()` (נקרא מהקשה על שורת ההודעה).

## בדיקות (Vitest) — מיפוי ל־Definition of Done

**Score Storage (`scoreStorage.test.ts`, עם Storage מדומה):**
- אין נתונים ← שני ערכים `null`.
- JSON פגום ← `null` בלי קריסה.
- ערכים מחוץ לטווח / לא שלמים / מחרוזת / שלילי / 11 ← נחשבים חסרים.
- `lastScore` תקין ו־`bestScore` חסר או קטן ממנו ← השיא מתוקן לפחות לתוצאה האחרונה.
- גישה ל־Storage זורקת / `getItem` זורק / `setItem` זורק ← אין קריסה; `saved: false`.
- רצף שמירות: 5 ← שיא 5, אחרון 5; אחר כך 2 ← שיא 5, אחרון 2; אחר כך 0 ← שיא 5, אחרון 0; 0 נשמר כ־0 ולא כ־`null`.
- שיא שמור גבוה יותר (למשל מלשונית אחרת) אינו יורד.

**Controller (טיימרים מדומים):**
- השהיה באמצע הצגה: אין יותר הדלקות / צלילים; גם אחרי 10 שניות אין timeout.
- השהיה באמצע תשובה (אחרי לחיצה נכונה אחת): אין timeout; בחזרה — מוצג אותו רצף בשלמותו, התשובה החלקית אופסה (צריך להקיש שוב מההתחלה), הניקוד ואורך הרצף לא השתנו.
- הזמן מתחיל רק אחרי סוף ההצגה החוזרת.
- השהיה בהמתנה שבין שלבים: בחזרה מוצג הרצף של השלב הבא, אורכו נכון והניקוד לא השתנה.
- `resumeIfPossible()` כשאין משחק מושהה ← לא עושה כלום; השהיה ב־`idle` / `finished` ← לא עושה כלום.
- לחיצות בזמן השהיה מתעלמות.
- אודיו שלא מתחדש בחזרה ← נשאר `paused`, הודעת „להמשך המשחק, הקישו כאן”, אין Deadline; `continueFromTap()` ← הצגה.
- השהיה בזמן ההמתנה לאודיו ← אין הצגה מאוחרת (Callback ישן מתעלם).
- סיום משחק קורא לשמירה פעם אחת עם התוצאה הנכונה (0 / 6 / 10); כשל שמירה ← ההודעה כוללת „לא ניתן לשמור ניקוד במכשיר זה.” והמשחק ממשיך כרגיל.

## נקודה לאישורך לפני הבנייה

**איפה „מקישים כאן”:** כשהדפדפן חוסם את הצליל בחזרה, ה־ARCHITECTURE מבקש להציג „להמשך המשחק, הקישו כאן” בתוך מסך הבית. ההצעה: **שורת ההודעה עצמה** היא המקום להקשה (בלי כפתור או חלון חדשים). אם תעדיף שהקשה בכל מקום על לוח הצבעים תמשיך את המשחק — אמור לי לפני הבנייה.
